Komponent to funkcja, która się powtarza

Największa różnica między Vue a Reactem nie leży w składni, tylko w tym, co się dzieje, gdy zmienia się stan. Kiedy to zrozumiesz, useEffect, useMemo i „dlaczego mój stan jest nieaktualny” przestaną być zagadką.

Po tej lekcjiPrzewidzisz, co pokaże komponent po kliknięciu, i wyjaśnisz na rozmowie, czym „render” w React różni się od reaktywności Vue.

Jak to robi Vue: śledzenie zależności

W Vue funkcja setup() (albo <script setup>) wykonuje się raz na instancję komponentu. Zwracasz z niej obiekty reaktywne. Vue opakowuje je w Proxy, zapamiętuje, które efekty (render szablonu, computed, watch) czytały dane pole, i przy zmianie uruchamia ponownie tylko je (Vue: Reactivity in Depth).

Twoja intuicja z Vue brzmi więc: „zmieniam wartość, framework wie, co od niej zależy”.

Jak to robi React: wywołaj funkcję jeszcze raz

W React komponent to zwykła funkcja zwracająca JSX. Renderowanie to wywołanie tej funkcji przez Reacta. Dzieje się tak przy pierwszym wyświetleniu i za każdym razem, gdy zmieni się stan komponentu (albo jego rodzica). React porównuje nowy wynik z poprzednim i zmienia w DOM tylko różnice (react.dev: Render and Commit).

Vue 3 
<script setup>
import { ref, computed } from 'vue'

// wykonuje się RAZ
const count = ref(0)
const double = computed(() => count.value * 2)
</script>

<template>
  <button @click="count++">{{ count }}</button>
  <p>{{ double }}</p>
</template>
React 19 
import { useState } from 'react'

function Counter() {
  // wykonuje się PRZY KAŻDYM renderze
  const [count, setCount] = useState(0)
  const double = count * 2 // zwykłe wyrażenie

  return (
    <>
      <button onClick={() => setCount(count + 1)}>
        {count}
      </button>
      <p>{double}</p>
    </>
  )
}

Zauważ: w React double nie potrzebuje żadnego computed. Funkcja i tak wykona się od nowa, więc wartość pochodna to po prostu zmienna. React nie śledzi zależności, tylko wywołuje całość ponownie.

Stan to zdjęcie, nie zmienna

Skoro funkcja wykonuje się wiele razy, skąd React wie, ile wynosi count? Przechowuje stan poza funkcją i przy każdym renderze podaje jego wartość. W ramach jednego renderu count jest stałą, czyli zdjęciem stanu z tej chwili. Wywołanie setCount nie zmienia tej stałej: prosi Reacta o następny render z nową wartością (react.dev: State as a Snapshot).

function handleClick() {
  setCount(count + 1)   // count == 0 → „ustaw 1 w następnym renderze”
  setCount(count + 1)   // count wciąż == 0 → „ustaw 1”
  setCount(count + 1)   // count wciąż == 0 → „ustaw 1”
  console.log(count)    // 0, bo to zdjęcie z bieżącego renderu
}
// po kliknięciu: 1, nie 3

Gdy nowa wartość zależy od poprzedniej, przekaż funkcję aktualizującą. React ustawi takie wywołania w kolejce i wykona je po kolei (react.dev: Queueing state updates):

setCount(c => c + 1)
setCount(c => c + 1)
setCount(c => c + 1) // po kliknięciu: +3
Sprawdź na żywo (prawdziwy React 19)

Ładowanie Reacta…

Co z tego wynika w praktyce

  • Wartości pochodne licz w ciele komponentu. Nie trzymaj ich w drugim useState synchronizowanym przez useEffect: to najczęstszy błąd ludzi z Vue (You Might Not Need an Effect). useMemo to optymalizacja na drogie obliczenia, a nie odpowiednik computed; React Compiler i tak często memoizuje za Ciebie (React Compiler).
  • Zwykła zmienna nie przetrwa renderu. let clicks = 0 w ciele komponentu resetuje się przy każdym wywołaniu. Do pamiętania wartości służy useState (zmiana wywołuje render) albo useRef (zmiana go nie wywołuje).
  • Funkcja komponentu musi być czysta. React może ją wywołać wiele razy, a w trybie deweloperskim (Strict Mode) celowo robi to dwukrotnie, żeby wyłapać efekty uboczne (Keeping Components Pure). Fetch, timery i mutacje idą do handlerów zdarzeń albo efektów.
  • Nie mutuj stanu. items.push(x) nic nie da, bo React porównuje referencje. Tworzysz nową tablicę: setItems([...items, x]). W Vue mutacja była mechanizmem, w React jest błędem.
Gdzie analogia z Vue się psujeuseEffect to nie watch. Efekt służy do synchronizacji z czymś poza Reactem (API przeglądarki, subskrypcja, zewnętrzna biblioteka), a nie do reagowania na zmianę stanu. Na zmianę stanu reagujesz w handlerze zdarzenia, który ją wywołał.

Sprawdź się

Odpowiadaj z pamięci, bez przewijania w górę. Wysiłek przypominania to właśnie moment, w którym wiedza się utrwala.

1. Co robi React, gdy w handlerze wywołasz setCount?

React nie śledzi zależności jak Vue. Zmiana stanu planuje render: funkcja komponentu wykona się ponownie, a React porówna wynik i zmieni w DOM tylko różnice.

2. count wynosi 0. Handler wywołuje trzy razy setCount(count + 1). Ile pokaże przycisk po kliknięciu?

count to zdjęcie z bieżącego renderu, więc każde wywołanie ustawia „0 + 1”. Żeby dostać 3, użyj funkcji aktualizującej: setCount(c => c + 1).

3. Jak w React zrobić odpowiednik computed dla fullName z firstName i lastName?

Funkcja komponentu i tak wykonuje się przy każdym renderze, więc const fullName = firstName + ' ' + lastName zawsze jest aktualne. Drugi stan + useEffect to dodatkowy render i ryzyko rozjazdu danych.

4. count wynosi 5. Handler wywołuje setCount(count + 1), a potem console.log(count). Co zobaczysz w konsoli?

W ramach tego renderu count pozostaje 5. Nowa wartość pojawi się dopiero w następnym wywołaniu funkcji komponentu.

5. Dlaczego funkcja komponentu musi być czysta (bez efektów ubocznych)?

Render może się wydarzyć wiele razy, a Strict Mode w trybie deweloperskim wywołuje komponent dwukrotnie właśnie po to, żeby ujawnić efekty uboczne w ciele funkcji.
